## 1. 项目概述

### 1.1 项目背景

中国支付产业年交易规模已突破 4000 万亿元（人民银行《2024 支付体系报告》），伴随交易量增长，欺诈交易规模同步攀升至 350 亿元/年。传统反欺诈方案面临三大瓶颈：

1. **规则引擎误报率高**：单一规则匹配误报率达 30%+，导致大量正常交易被拦截，影响用户体验
2. **新型欺诈识别滞后**：从欺诈模式出现到规则更新平均需 7-14 天，期间损失已成规模
3. **单模态漏检率高**：仅依赖交易金额/频率等结构化数据，无法识别基于社交工程/账号盗用的复合欺诈

本项目源于对 DWS（心理健康风险评估系统）多模态融合方法论的迁移探索：将「结构化 + 文本 + 行为」三模态融合架构应用到金融反欺诈场景，结合图神经网络（GNN）团伙检测，构建实时（P99 < 200ms）+ 离线（图分析）双层反欺诈引擎。

### 1.2 项目定位

**面向持牌金融机构（银行/支付公司/消费金融）+ 商户的实时反欺诈 SaaS 平台**，核心能力：

- 实时评分：单笔交易评分 P99 < 200ms，支持每秒 1000+ 笔交易
- 多模态融合：交易结构化 + 备注文本 + 行为时序 三模态加权
- 团伙检测：GNN 挖掘账户-商户-设备关联，识别洗钱链路
- 双轨设计：ML 引擎 + 规则引擎并行，规则兜底保证可解释性
- 合规内建：PCI-DSS 隔离区 + 反洗钱（AML）报告 + 数据保留 7 年

### 1.3 项目目标

| 目标类型 | 目标描述 | 量化指标 |
|---|---|---|
| 业务目标 | 降低欺诈漏检率 | 较规则引擎下降 ≥ 60% |
| 业务目标 | 控制误报率 | ≤ 5%（行业平均 30%） |
| 技术目标 | 实时评分延迟 | P99 < 200ms |
| 技术目标 | 系统吞吐 | ≥ 1000 TPS / 单实例 |
| 合规目标 | PCI-DSS | 通过 QSA 季度评估 |
| 合规目标 | 数据保留 | 交易 7 年 + 案件 10 年 |
| 合规目标 | 反洗钱 | 接入人行反洗钱监测系统 |

**基线说明**：降低欺诈漏检率 ≥ 60% 的基线为 FR-RULE 默认规则集在 IEEE-CIS 数据集上的漏检率（即在同一样本集上，FR-RULE 的漏检率与 FRD-ML/GNN 系统的漏检率对比，下降比例 ≥ 60%）。该基线在 M3 设计基线前由 ML Agent + REQ Agent 联合输出《基线评估报告》固化。

## 3. 市场与竞品分析

### 3.1 市场规模

> 计算口径：以中国金融机构总数 × 单家年付费 50 万元测算；数据来源为国家金融监督管理总局公开披露。

- **TAM（潜在市场）**：中国金融机构 4600 家 × 年付费 50 万元 = 230,000 万元 = **23 亿元**
- **SAM（可服务市场）**：中型金融机构 800 家 × 年付费 50 万元 = 40,000 万元 = **4 亿元**
- **SOM（可获取市场）**：3 年内获取 SAM 的 2% 份额 = 4 亿元 × 2% = **800 万元**

**修订说明**：V1.0 错将 TAM 写为 230 亿、SAM 写为 40 亿、SOM 写为 8000 万，单位换算错误。本次按统一基准修正为 23 亿 / 4 亿 / 800 万。

### 3.3 差异化优势

1. **方法论可复用**：复用 DWS 多模态融合方法论 + 金丝雀治理
2. **双轨设计**：规则引擎兜底保证可解释性 + ML 引擎提升召回率
3. **GNN 实时化**：图查询 P99 < 2s（千万级节点）
4. **PCI-DSS 原生**：网络隔离区设计 + tokenization 替代明文卡号

**补注**：FICO Falcon 较新版本（2024 年后）已具备 GNN 能力，本表所列「FICO Falcon GNN ✗」基于公开资料较早版本；实际竞品分析应在 M2 需求基线前由 REQ Agent 重新复核最新版本能力，避免技术路线误判。FRD 的核心差异化应聚焦于「开源自部署 + 中国合规 + 多模态融合」组合，而非 GNN 本身。

## 5. 技术可行性分析

### 5.1 技术选型对比

| 维度 | 方案 A | 方案 B | 决策 |
|---|---|---|---|
| 后端框架 | FastAPI（async） | Spring Boot | **A**：复用 DWS + Python ML 生态 |

### 8.3 立项决策

**立项结论**：✅ **有条件通过立项**

**决策依据**：
1. **技术可行性中等**（修订）：55% 复用 DWS 模块 + Neo4j/PyG 可学习；但流处理/图数据库/GNN/金融业务/PCI-DSS 五项存在较大到极大差距（见 §5.3），需通过 PoC 验证 GNN 与实时性。原 V1.0「技术可行性高」与 §5.3 团队差距评估存在矛盾，本次修正为「中等」。
2. **商业价值大但需谨慎**（修订）：ROI 24 月中性 125%（远低于原 620%），目标市场 4 亿（原误写 40 亿）。商业价值仍为正，但需结合客户获取风险（R07）谨慎评估。
3. **风险可控**：Top10 风险均有应对方案，新增 R06-R10 覆盖单人项目特有风险。
4. **简历差异化**：金融科技 + GNN + 实时 ML 是热门方向。

**附加条件**：
- M2 需求基线前完成 QSA 顾问选型
- M3 设计基线前完成 PCI-DSS 隔离区方案评审
- M5 Beta 前完成等保 2.0 三级备案（注意 R09 时长风险，M1 即启动）
- M7 生产部署前完成 PCI-DSS QSA 评估
- **M2 前完成 GNN + 实时评分技术 Spike**（PoC 准入条件，验证 GNN 团伙检测效果与 P99 < 200ms 可达性；Spike 不通过则立项需重新评估）

> **Spike 进展（V1.2 补注，截至 2026-07-27）**：该 Spike 已提前启动——GNN 侧（gnn/ 目录：GraphSAGE 模型、建图训练、Louvain/标签传播团伙检测、Neo4j graph_service）与实时评分侧（backend 评分编排器：Tokenization + 双轨并行 + 决策融合 + Kill Switch 兜底）骨架代码均已入库；ML 当前为启发式 Mock，真模型按 M5 节点接入。剩余 Spike 验证项：GNN 团伙检测效果评估与 P99 < 200ms 压测验证，预计 M2（2026-09-05）前完成并输出《Spike 验证报告》。
