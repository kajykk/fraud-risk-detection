## 1. 项目概述

### 1.1 项目背景

针对金融机构面临的实时欺诈风险，构建一个面向持牌金融机构的反欺诈 SaaS 平台，集成规则引擎、ML 多模态融合、GNN 团伙检测三大核心能力，满足 PCI-DSS v4.0、PIPL、反洗钱法合规要求。

### 1.2 项目周期

| 阶段 | 起止时间 | 工期 |
|------|----------|------|
| 启动 | 2026-08-01 ~ 2026-08-15 | 2 周 |
| 需求与设计 | 2026-08-18 ~ 2026-09-15 | 4 周 |
| 开发 | 2026-09-15 ~ 2027-01-15 | 18 周 |
| 测试 | 2026-12-01 ~ 2027-01-31 | 9 周（与开发重叠 6 周） |
| 上线 | 2027-02-01 ~ 2027-02-28 | 4 周 |
| 试运行 | 2027-03-01 ~ 2027-04-30 | 8 周 |
| **总计** | **2026-08-01 ~ 2027-04-30** | **9 个月** |

### 1.3 项目目标

- **功能目标**：交付 FRD-D02 需求规格说明书全部功能
- **质量目标**：单元测试通过率 ≥ 99%，契约测试 100%，安全 0 高危
- **性能目标**：评分接口 P99 < 200ms，TPS ≥ 2000
- **合规目标**：通过 PCI-DSS v4.0 / PIPL / 反洗钱法合规审计
- **交付目标**：2027-02-28 完成生产部署，2027-04-30 完成试运行验收

## 2. 项目范围

### 2.1 包含范围

| 模块 | 描述 | 优先级 |
|------|------|--------|
| API 网关 | 认证、限流、路由 | P0 |
| 评分引擎 | 规则 + ML 双轨决策 | P0 |
| 规则引擎 | DSL、试运行、版本管理 | P0 |
| ML 引擎 | XGBoost + BERT + 漂移检测 | P0 |
| GNN 服务 | 团伙检测、子图查询 | P0 |
| 案件管理 | 工作流、SLA、审计 | P0 |
| 报表中心 | 标准报表 + 自定义 + 导出 | P1 |
| 模型治理 | 金丝雀、回滚、Kill Switch | P0 |
| 前端 UI | 5 端控制台 | P0 |
| 合规审计 | PCI-DSS / PIPL / 反洗钱 | P0 |
| 可观测性 | Prometheus + Grafana + Sentry | P1 |
| 部署 | K8s 多 AZ + CI/CD | P0 |

### 2.2 不包含范围

- 客户端 SDK（仅做集成测试）
- 第三方数据源内部实现（设备指纹、IP 库）
- 反洗钱上报通道（对接监管接口）
- 客户培训与运营（另行立项）

### 2.3 假设与约束

- 假设：客户能提供 6 个月历史交易数据用于模型训练
- 假设：合规审计员全程参与合规测试
- 约束：PCI-DSS v4.0 强制要求
- 约束：2027-02-28 上线硬截止
- 约束：开发团队 6 人

| 测试通过率 | 通过 / 总数 | ≥ 99% |
| 关键路径浮动 | 关键路径剩余浮动 | ≥ 0 |

### 12.2 监控工具

- **Jira**：任务跟踪、缺陷管理
- **GitHub Project**：开发任务看板
- **CI/CD Dashboard**：构建状态
- **Grafana**：测试通过率、覆盖率趋势

### 12.3 偏差处理

| 偏差 | 处理 |
|------|------|
| < 5% | 项目内部消化 |
| 5%-10% | PM 评估并通知干系人 |
| 10%-20% | 启动赶工或快速跟进 |
| > 20% | 变更控制委员会评估 |

### 12.4 挣值管理（EVM）

每月计算：

- **PV**（计划价值）：计划完成工作的预算
- **EV**（挣值）：实际完成工作的预算
- **AC**（实际成本）：实际完成工作的实际成本
- **SV = EV - PV**（进度偏差）
- **CV = EV - AC**（成本偏差）
- **SPI = EV / PV**（进度绩效指数）
- **CPI = EV / AC**（成本绩效指数）

| 指标 | 健康 | 警告 | 危险 |
|------|------|------|------|
| SPI | ≥ 0.95 | 0.85-0.95 | < 0.85 |
| CPI | ≥ 0.95 | 0.85-0.95 | < 0.85 |
