## 1. 项目概述

### 1.1 项目背景

针对金融机构面临的实时欺诈风险，构建一个面向持牌金融机构的反欺诈 SaaS 平台，集成规则引擎、ML 多模态融合、GNN 团伙检测三大核心能力，满足 PCI-DSS v4.0、PIPL、反洗钱法、等保 2.0 三级合规要求。

本项目采用 **"1 真人 + 11 AI Agent + 3 外聘顾问"** 协作模式：邝振华作为唯一真人决策者，对全部 AI Agent 产出负终审责任；11 AI Agent 为分工角色（非真人雇员），承担 PM/REQ/ARCH/BE×2/FE/ML/GNN/DevOps/QA/SEC 职责；3 外聘顾问提供 QSA 评估、法律审阅、金融业务咨询。

### 1.2 项目周期

| 阶段 | 起止时间 | 工期 |
|------|----------|------|
| 启动 | 2026-08-01 ~ 2026-08-15 | 2 周 |
| 需求与设计 | 2026-08-18 ~ 2026-09-30 | 6 周 |
| 开发 | 2026-10-08 ~ 2027-01-31 | 17 周（含国庆顺延） |
| 测试 | 2026-12-01 ~ 2027-01-31 | 9 周（与开发重叠 6 周） |
| 上线 | 2027-02-01 ~ 2027-02-28 | 4 周（含 M6→M7 缓冲周） |
| 试运行 | 2027-03-01 ~ 2027-04-30 | 8 周 |
| **总计** | **2026-08-01 ~ 2027-04-30** | **9 个月** |

### 1.3 项目目标

- **功能目标**：交付 FRD-D02 需求规格说明书全部功能
- **质量目标**：单元测试通过率 ≥ 99%，行覆盖率 ≥ 85%（评分/规则引擎核心 ≥ 90%，ML/GNN ≥ 75%），契约测试 100%，安全 0 高危
- **性能目标**：评分接口 P99 < 200ms，TPS ≥ 2000（MVP）/ ≥ 10000（生产扩容后）
- **合规目标**：通过 PCI-DSS v4.0 / PIPL / 反洗钱法 / 等保 2.0 三级合规审计
- **交付目标**：2027-02-28 完成生产部署，2027-04-30 完成试运行验收

- 客户培训与运营（另行立项）

- 假设：客户能提供 6 个月历史交易数据用于模型训练
- 假设：合规审计员全程参与合规测试
- 假设：AI Agent 协作工具（Trae/Cursor/Claude Code）与 LLM API（通义千问/DeepSeek）稳定可用
- 约束：PCI-DSS v4.0 强制要求
- 约束：2027-02-28 上线硬截止
- 约束：1 真人 + 11 AI Agent 协作模式

### 12.3 偏差处理

| 偏差 | 处理 |
|------|------|
| < 5% | 项目内部消化 |
| 5%-10% | PM Agent 评估并通知干系人 |
| 10%-20% | 启动赶工或快速跟进 |
| > 20% | 变更控制委员会（CCB）评估 |

> **AI Agent 任务偏差补充**：AI Agent 任务偏差由真人即时 review 调整（不等待 CCB 周期），通过每日 GitHub Projects sync + 每周架构 review 快速识别并纠正。

### 12.4 挣值管理（EVM）

每月计算：

- **PV**（计划价值）：计划完成工作的预算
- **EV**（挣值）：实际完成工作的预算
- **AC**（实际成本）：实际完成工作的实际成本
- **SV = EV - PV**（进度偏差）
- **CV = EV - AC**（成本偏差）
- **SPI = EV / PV**（进度绩效指数）
- **CPI = EV / AC**（成本绩效指数）

| 指标 | 健康 | 警告 | 危险 |
|------|------|------|------|
| SPI | ≥ 0.95 | 0.85-0.95 | < 0.85 |
| CPI | ≥ 0.95 | 0.85-0.95 | < 0.85 |
