## 1. 手册导读

### 1.1 适用对象

本手册适用于以下用户角色：

- **风控分析师**（Analyst）：处理案件、查询交易、分析团伙
- **规则运营员**（Rule Operator）：维护规则引擎
- **模型工程师**（ML Engineer）：管理模型生命周期
- **合规审计员**（Compliance Officer）：审计反洗钱、PIPL 合规
- **租户管理员**（Tenant Admin）：账号、权限、配置管理

### 1.2 阅读建议

- 新用户：先阅读 §2-§4 完成入门
- 风控分析师：重点 §5-§6、§9
- 模型工程师：重点 §8
- 合规审计员：重点 §11

### 1.3 文档约定

| 标记 | 含义 |
|------|------|
| ℹ️ | 提示信息 |
| ⚠️ | 注意事项 |
| 🔥 | 严重警告 |
| ✅ | 操作成功 |
| 📋 | 操作前准备 |

## 2. 角色与权限

### 2.1 角色矩阵

| 角色 | 案件 | 规则 | 模型 | GNN | 报表 | 审计 | 系统管理 |
|------|------|------|------|-----|------|------|----------|
| Analyst | R/W | R | R | R | R | - | - |

| ML Engineer | R | R | R/W | R | R | - | - |

- 所有跨租户操作记录到审计日志

## 3. 登录与账号

### 3.1 首次登录

1. 收到管理员发送的激活邮件
2. 点击邮件中的激活链接，设置初始密码（8-32 位，必须包含大小写字母+数字+特殊字符）
3. 启用 MFA（TOTP，如 Google Authenticator）
4. 扫描二维码绑定，输入 6 位动态码完成绑定
5. 保存恢复码（10 个）到安全位置

### 3.2 日常登录

1. 访问 `https://app.fraud-detection.example.com`
2. 输入用户名/邮箱 + 密码
3. 输入 MFA 动态码
4. （可选）勾选"信任此设备 7 天"

⚠️ 连续 5 次密码错误，账号锁定 15 分钟。

### 3.3 密码重置

1. 登录页点击"忘记密码"
2. 输入注册邮箱
3. 收到重置链接（有效期 30 分钟）
4. 设置新密码
5. 系统会强制要求重新登录所有设备

### 3.4 个人设置

路径：右上角头像 → 个人设置

- 修改密码
- 重新绑定 MFA
- 通知偏好（邮件/短信/Webhook）
- API Token 管理（生成/吊销）
- 会话管理（查看/注销活跃会话）

## 5. 实时交易监控

### 5.1 进入路径

侧边栏 → 交易 → 实时监控

### 5.2 交易流列表

- 实时滚动展示最近 200 条交易
- 按风险着色：绿色 ALLOW / 黄色 REVIEW / 红色 DENY
- 双击行展开详情：模型评分、规则命中、SHAP 解释

### 5.3 查询交易

📋 支持的查询条件：
- `external_tx_id`（精确）
- `decision`（ALLOW/REVIEW/DENY/CHALLENGE）
- `risk_band`（LOW/MEDIUM/HIGH/CRITICAL）
- 时间范围（最长 90 天）
- 金额范围
- 商户 ID / 持卡人 ID / 卡 BIN
- 模型版本

### 5.4 交易详情页

包含以下标签页：

1. **基本信息**：交易参数、决策、风险评分
2. **模型解释**：SHAP 特征贡献图、TOP-10 重要特征
3. **规则命中**：命中的规则列表、规则版本、DSL
4. **图关系**：账户/卡/设备/IP 的子图（默认 2 跳）
5. **历史行为**：持卡人 30 天交易画像
6. **案件关联**：关联的案件 ID 与时间线
7. **反馈**：提交欺诈标签

### 5.5 反馈真实标签

风控分析师可以在交易详情页点击"标记为欺诈"或"标记为非欺诈"，标签将进入模型再训练数据集。

ℹ️ 标签来源：
- `CHARGEBACK`：拒付调单
- `MANUAL_REVIEW`：人工核实
- `POLICE_REPORT`：报案记录
- `EXTERNAL_LIST`：外部黑名单匹配

## 6. 案件管理

### 6.1 案件列表

路径：侧边栏 → 案件 → 全部案件

支持的视图：
- **全部案件**：默认列表
- **我的待办**：分配给我的 OPEN 案件
- **未分配**：待分配案件
- **已逾期**：超过 SLA 的案件
- **已关闭**：最近 30 天已结案案件

### 6.2 创建案件

1. 点击右上角"新建案件"
2. 填写：
   - 关联交易号（可多选）
   - 优先级（P0/P1/P2/P3）
   - 处理人
   - 描述
   - 标签（chargeback/dispute/high_value 等）
3. 点击"创建"

✅ 案件 ID 自动生成，分配人收到通知。

### 6.3 处理案件

#### 6.3.1 案件详情页

- **顶部**：案件 ID、状态、优先级、SLA 倒计时
- **左侧**：关联交易列表、关联团伙、关联账户
- **右侧**：时间线、备注、附件

#### 6.3.2 工作流

```
OPEN（创建） → IN_REVIEW（处理中） → CONFIRMED（确认为欺诈）
                                ↓
                          FALSE_ALARM（误报）
                                ↓
                          CLOSED（已结案）
```

#### 6.3.3 SLA 标准

| 优先级 | 响应 SLA | 解决 SLA |
|--------|----------|----------|
| P0 | 15 分钟 | 4 小时 |
| P1 | 1 小时 | 24 小时 |
| P2 | 4 小时 | 72 小时 |
| P3 | 24 小时 | 7 天 |

⚠️ 超过 SLA 的案件会自动升级到处理人的上级。

### 6.4 添加备注

1. 案件详情页右侧"备注"区
2. 输入备注内容
3. （可选）@提及同事
4. 点击"提交"

ℹ️ 备注一旦提交不可删除，仅可编辑（保留历史版本）。

### 6.5 上传附件

支持格式：PDF、PNG、JPG、CSV、XLSX，单文件 ≤ 50MB。

🔥 严禁上传明文 PAN（卡号），系统会自动扫描并阻断。

### 6.6 结案

1. 点击"结案"按钮
2. 选择结案结论：
   - `CONFIRMED_FRAUD`：确认欺诈
   - `FALSE_ALARM`：误报
   - `INCONCLUSIVE`：证据不足
3. 填写：
   - 损失金额（分）
   - 挽回金额（分）
   - 是否上报反洗钱
   - 结案说明
4. 二次确认后提交

✅ 结案后案件进入只读状态，可重新打开（生成新案件 ID）。

### 6.7 案件导出

- 列表页右上角"导出"按钮
- 支持 CSV / Excel
- 含完整审计字段
- 导出操作记录到审计日志

## 7. 规则引擎管理

### 7.1 规则列表

路径：侧边栏 → 规则 → 全部规则

### 7.2 规则生命周期

```
DRAFT（草稿） → REVIEWING（评审中） → PUBLISHED（已发布）
                                       ↓
                                  DISABLED（已下线）
                                       ↓
                                  ARCHIVED（归档）
```

### 7.3 创建规则

📋 操作前准备：
- 已分析业务场景
- 已准备 DSL 草稿
- 已评估潜在误报影响

#### 7.3.1 DSL 语法

```sql
-- 简单条件
amount > 1000000 AND hour_of_day BETWEEN 2 AND 5

-- 复杂条件（带聚合）
SUM(amount, 1h, user_id) > 5000000
  AND COUNT(DISTINCT merchant_id, 1h, user_id) > 5
  AND ip_country != billing_country

-- 引用外部变量
device_age_sec < 600
  AND user_total_tx_count < 3
```

#### 7.3.2 操作步骤

1. 点击"新建规则"
2. 填写名称、描述
3. 编写 DSL
4. 选择严重级别（INFO/WARN/BLOCK）
5. 选择动作（REVIEW/DENY/CHALLENGE）
6. 配置生效时间范围
7. 配置渠道范围
8. 保存为草稿

### 7.4 DSL 校验与试运行

1. 规则详情页点击"校验"
2. 系统自动检查语法
3. （可选）选择样本交易进行试运行
4. 查看命中率、误报率预估

⚠️ 试运行不会影响生产决策，仅返回模拟结果。

### 7.5 规则评审与发布

#### 7.5.1 提交评审

1. 草稿完成后点击"提交评审"
2. 选择评审人（至少 1 名，建议 2 名）
3. 填写变更说明

#### 7.5.2 评审

- 评审人收到通知
- 查看变更对比（diff）
- 批准 / 拒绝（含意见）
- 至少 1 名评审人批准后可发布

#### 7.5.3 发布

1. 评审通过后点击"发布"
2. 二次确认
3. 规则进入 ACTIVE 状态
4. 默认 5 分钟内全节点生效

🔥 严重级别为 BLOCK 的规则发布需 Tenant Admin 二次确认。

### 7.6 规则监控

- **命中率**：24h/7d/30d 命中次数与占比
- **误报率**：基于结案数据反推
- **性能**：平均执行时间
- **趋势图**：命中数趋势

⚠️ 误报率 > 30% 的规则系统会自动告警，建议下线优化。

### 7.7 规则下线

1. 规则详情页点击"下线"
2. 选择下线原因
3. 二次确认
4. 规则进入 DISABLED 状态
5. 30 天后自动归档

## 8. ML 模型治理

### 8.1 模型列表

路径：侧边栏 → 模型 → 全部模型

字段：
- 模型 ID / 版本
- 状态：`TRAINING` / `STAGING` / `CANARY` / `PRODUCTION` / `ARCHIVED`
- 流量比例
- AUC / Precision / Recall
- 训练时间 / 上线时间

### 8.2 模型详情

#### 8.2.1 性能指标

- AUC、PR-AUC、KS
- Precision@1%、Recall@1%
- F1、MCC
- 延迟分布（P50/P95/P99）
- 各子集表现（按金额段、渠道、商户类别）

#### 8.2.2 特征重要性

- 全局特征重要性（Gain / Weight）
- 特征稳定性（PSI）
- 特征覆盖度

#### 8.2.3 漂移监控

- 整体 PSI（1d / 7d / 30d）
- KL 散度
- 各特征 PSI 排行
- 预测分布对比

### 8.3 金丝雀发布

#### 8.3.1 启动金丝雀

1. 选择候选模型（必须为 STAGING 状态）
2. 配置：
   - 初始流量比例（默认 5%）
   - 回滚阈值（precision_drop / latency / error_rate）
   - 观察期（默认 24h）
3. 提交评审
4. ML Engineer + Tenant Admin 双确认
5. 启动金丝雀

#### 8.3.2 三阶段推进

```
Stage 1: 5% 流量，24h 观察
   ↓ 满足阈值
Stage 2: 25% 流量，24h 观察
   ↓ 满足阈值
Stage 3: 100% 流量（晋升为 PRODUCTION）
```

ℹ️ 任何阶段触发回滚阈值，系统自动回滚到上一稳定版本。

#### 8.3.3 推进流量

1. 金丝雀详情页点击"推进到下一阶段"
2. 系统校验上一阶段是否满足条件
3. 二次确认
4. 流量比例自动调整

#### 8.3.4 紧急回滚

1. 金丝雀详情页点击"紧急回滚"
2. 填写回滚原因
3. 二次确认
4. 流量立即切回上一稳定版本（< 30s）
5. 自动触发告警通知

### 8.4 模型回退策略

系统在 ML 引擎异常时按以下顺序回退：

```
BERT 文本模型 → TF-IDF/LR → 启发式规则 → 纯规则引擎
```

### 8.5 Kill Switch

🔥 **紧急熔断开关**

- 路径：模型 → 治理 → Kill Switch
- 触发后立即关闭 ML 引擎，所有交易走纯规则模式
- 需填写：原因、持续时长（最长 24h）、审批人
- 启动后系统进入"降级模式"告警状态

## 9. GNN 团伙检测

### 9.1 进入路径

侧边栏 → GNN → 团伙检测

### 9.2 触发检测

#### 9.2.1 手动触发

1. 点击"新建检测任务"
2. 选择种子账户（可多选）或上传 CSV
3. 配置：
   - 深度（1-3 跳）
   - 时间窗口（默认 7 天）
   - 最小置信度（默认 0.6）
4. 提交，任务异步执行

#### 9.2.2 自动触发

系统在以下场景自动触发团伙检测：
- 单笔交易 risk_score > 0.9
- 同设备/IP 24h 内绑定 ≥ 5 张卡
- 反洗钱告警

### 9.3 任务列表

- 任务 ID、状态（PENDING/RUNNING/SUCCESS/FAILED）
- 种子账户数
- 检测时长
- 检测到的团伙数

### 9.4 团伙详情

#### 9.4.1 概览

- 团伙 ID、置信度、规模
- 涉案总金额
- 检测时间
- 关联案件数

#### 9.4.2 图谱可视化

交互式图谱：
- 节点：账户、商户、设备、IP、卡
- 边：USES / PAYS_TO / FROM_IP / BINDS_TO / SHARES_WITH
- 节点颜色按风险评分着色
- 支持缩放、拖拽、过滤

#### 9.4.3 节点详情

点击节点查看：
- 节点属性
- 关联交易数
- 历史风险评分
- 是否在黑名单

### 9.5 团伙处置

1. 团伙详情页点击"创建案件"
2. 选择关联账户/交易
3. 自动填充案件描述
4. 提交后生成案件，分配给处理人

### 9.6 上报反洗钱

合规审计员可将团伙案件上报反洗钱系统：
1. 案件详情页点击"上报反洗钱"
2. 填写上报类型（STR 可疑交易报告/CTR 大额交易报告）
3. 生成报告 PDF
4. 提交后状态变为"已上报"

## 10. 报表中心

侧边栏 → 报表

### 10.2 标准报表

| 报表 | 频率 | 默认接收人 |

## 11. 审计与合规

### 11.1 审计日志查询

路径：侧边栏 → 审计 → 操作日志

支持的查询条件：
- 操作人
- 操作类型（LOGIN/RULE_PUBLISH/MODEL_PROMOTE/CASE_CLOSE 等）
- 资源类型
- 时间范围
- IP 地址

### 11.2 审计日志详情

每条日志包含：
- 操作时间
- 操作人 ID / 姓名 / IP
- 操作类型
- 资源类型 / 资源 ID
- 变更前后对比（before/after）
- 请求 ID / Trace ID

ℹ️ 审计日志保留 7 年（满足反洗钱法要求）。

### 11.3 数据导出合规

PIPL 个人信息保护要求：

1. **数据导出请求**：用户可申请导出个人数据
2. **数据删除请求**：用户可申请删除个人数据（保留法律要求的最小集）
3. **数据使用审计**：可查询个人数据被访问的记录

操作路径：审计 → PIPL 合规 → 数据主体请求

### 11.4 反洗钱上报

合规审计员可生成反洗钱报告：

1. 案件详情页或团伙详情页点击"上报反洗钱"
2. 选择上报类型：
   - STR（Suspicious Transaction Report，可疑交易报告）
   - CTR（Currency Transaction Report，大额交易报告）
3. 系统自动汇总相关交易、账户、团伙信息
4. 生成 PDF 报告（含数字签名）
5. 通过加密通道上报到反洗钱监测中心
6. 系统留存上报凭证 7 年

### 11.5 PCI-DSS 卡数据保护

🔥 **严禁在系统中存储明文 PAN（主账号）**

- 上传文件/备注时系统自动扫描，发现疑似 PAN 立即阻断
- 卡数据仅以 Token 形式存储
- 卡 BIN + last4 用于风险分析，不可逆推 PAN
- 任何截屏/导出操作都会被审计

## 13. 常见问题

### 13.1 登录问题

**Q: 忘记密码怎么办？**
A: 登录页点击"忘记密码"，通过邮箱重置。如邮箱不可用，联系 Tenant Admin 重置。

**Q: MFA 设备丢失怎么办？**
A: 使用恢复码登录后重新绑定 MFA。如恢复码也丢失，联系 Tenant Admin 重置（需身份验证）。

**Q: 账号被锁定怎么办？**
A: 等待 15 分钟自动解锁，或联系 Tenant Admin 手动解锁。

### 13.2 业务问题

**Q: 交易被误判为欺诈怎么办？**
A: 在交易详情页标记为"NOT_FRAUD"反馈，并创建案件记录误报，规则运营员可优化规则。

**Q: 规则命中率突降怎么办？**
A: 检查上游数据源是否正常，规则 DSL 是否依赖异常字段，必要时下线规则并联系 ML Engineer。

**Q: 模型 AUC 下降怎么办？**
A: 检查漂移 PSI，如 > 0.25 触发再训练。可在模型详情页查看影响 AUC 的因素，并启动金丝雀发布新模型。

**Q: 金丝雀发布失败如何回滚？**
A: 系统会自动回滚。如未自动触发，可手动点击"紧急回滚"，30 秒内流量切回。

### 13.3 合规问题

**Q: 如何生成反洗钱报告？**
A: 案件详情页点击"上报反洗钱"，选择上报类型，系统自动生成 PDF 报告。

**Q: 审计日志能否删除？**
A: 不能。审计日志不可篡改、不可删除，保留 7 年。

**Q: 如何申请数据导出？**
A: 联系 Compliance Officer，提交数据主体请求，系统将在 30 天内响应。

### 13.4 性能问题

**Q: API 调用频繁返回 429 怎么办？**
A: 已触发限流，请检查 QPS 是否超出租户级别限制，必要时升级租户级别或优化调用方批量逻辑。

**Q: 评分延迟突增怎么办？**
A: 查看仪表盘 P99 延迟指标，如超过 200ms 告警阈值，检查 ML 引擎健康状态，必要时启用 Kill Switch 降级到纯规则模式。
