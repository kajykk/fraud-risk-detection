## 1. 手册导读

### 1.1 适用对象

本手册适用于以下 7 类用户角色（依据 FRD-BASELINE-V1.1 §1 项目定位，1 真人 + 11 AI Agent 模式下的用户角色矩阵）：

- **租户管理员**（TENANT_ADMIN）：账号、权限、租户配置、系统管理
- **商户管理员**（MERCHANT_ADMIN）：商户入驻、仪表盘、交易查询、申诉、Webhook、API Key
- **风控分析师**（RISK_ANALYST）：处理案件、查询交易、分析团伙
- **风控经理**（RISK_MANAGER）：团队任务分配、SLA 监控、规则/模型审批、KPI 看板
- **审计员**（AUDITOR）：审计日志、合规审查
- **合规官**（COMPLIANCE_OFFICER）：反洗钱、PIPL 合规、合规报表
- **运维工程师**（DEVOPS_OPS）：系统部署、可观测性、Kill Switch、灾备

- 新用户：先阅读 §2-§4 完成入门

## 2. 角色与权限

### 2.1 角色矩阵（7 类角色 × 8 个功能模块）

依据 FRD-BASELINE-V1.1 §1 项目定位，系统采用 1 真人 + 11 AI Agent 团队模式，对外提供 7 类用户角色。下表为各角色对 8 个功能模块的访问权限矩阵。

| 功能模块 \ 角色 | TENANT_ADMIN | MERCHANT_ADMIN | RISK_ANALYST | RISK_MANAGER | AUDITOR | COMPLIANCE_OFFICER | DEVOPS_OPS |
|------|------|------|------|------|------|------|------|
| 评分查询 | R | R（自有商户） | R/W | R | R | R | R |
| 案件管理 | R | R（自有申诉） | R/W | R/W（团队） | R | R | - |
| 规则配置 | R/W | - | R | R/W（审批） | R | R | - |
| 模型管理 | R/W | - | R | R/W（审批） | R | R | R/W（运维） |
| 申诉审核 | R | - | R/W | R/W | R | R | - |
| 合规报表 | R/W | R（自有） | R | R | R | R/W | R |
| 系统配置 | R/W | R（自有商户） | - | - | - | - | R/W |
| 审计日志 | R | - | - | R | R/W | R | R |

R = 只读，R/W = 读写，- = 无权限

ℹ️ 说明：
- MERCHANT_ADMIN 的所有权限均限定在"自有商户"范围内，由 PostgreSQL RLS（行级安全）强制隔离，跨商户数据不可见。
- RISK_MANAGER 的"案件管理"权限覆盖其下属团队，可重分配与监督团队案件。
- AUDITOR 对审计日志为 R/W，可标注、加签、导出审计证据，但不可篡改原始日志。
- DEVOPS_OPS 的"模型管理"权限仅限运维操作（启停、回滚、Kill Switch），不涉及模型训练与发布审批。

### 2.2 多租户隔离

- 每个用户仅能访问所属租户的数据
- 所有业务表启用 PostgreSQL RLS（Row Level Security），策略为 `tenant_id = current_setting('app.tenant_id')::uuid`
- 跨租户访问需通过 TENANT_ADMIN 提交审批工单
- 所有跨租户操作记录到审计日志，保留 7 年

### 2.3 角色与 AI Agent 对应关系

| 用户角色 | 主要对接的 AI Agent（开发/维护方） |
|------|------|
| TENANT_ADMIN | PM Agent / DEVOPS Agent |
| MERCHANT_ADMIN | BE-2 Agent（案件/报表/模型治理/Webhook）|
| RISK_ANALYST | BE-2 Agent / GNN Agent |
| RISK_MANAGER | BE-2 Agent / ML Agent |
| AUDITOR | SEC Agent |
| COMPLIANCE_OFFICER | SEC Agent |
| DEVOPS_OPS | DevOps Agent |

## 3. 登录与账号

### 3.1 首次登录

![首次登录激活页面](screenshots/03_first_login_activate.png)

1. 收到管理员发送的激活邮件
2. 点击邮件中的激活链接，设置初始密码（≥14 位，必须包含大小写字母+数字+特殊字符，PCI-DSS 8.3）
3. 启用 MFA（TOTP，如 Google Authenticator）
4. 扫描二维码绑定，输入 6 位动态码完成绑定
5. 保存恢复码（10 个）到安全位置

### 3.2 日常登录

![日常登录页面](screenshots/03_daily_login.png)

1. 访问 `https://app.fraud-detection.example.com`
2. 输入用户名/邮箱 + 密码
3. 输入 MFA 动态码
4. （可选）勾选"信任此设备 7 天"

⚠️ 连续 5 次密码错误，账号锁定 15 分钟。

### 3.3 密码重置

1. 登录页点击"忘记密码"
2. 输入注册邮箱
3. 收到重置链接（有效期 30 分钟）
4. 设置新密码
5. 系统会强制要求重新登录所有设备

### 3.4 个人设置

路径：右上角头像 → 个人设置

- 修改密码
- 重新绑定 MFA
- 通知偏好（邮件/短信/Webhook）
- API Token 管理（生成/吊销）
- 会话管理（查看/注销活跃会话）

## 5. 实时交易监控

### 5.1 进入路径

侧边栏 → 交易 → 实时监控

### 5.2 交易流列表

![实时交易流列表](screenshots/05_realtime_tx_stream.png)

- 实时滚动展示最近 200 条交易
- 按风险着色：绿色 ALLOW / 黄色 REVIEW / 红色 DENY
- 双击行展开详情：模型评分、规则命中、SHAP 解释

### 5.3 查询交易

📋 支持的查询条件：
- `external_tx_id`（精确）
- `decision`（ALLOW/REVIEW/DENY/CHALLENGE）
- `risk_band`（LOW/MEDIUM/HIGH/CRITICAL）
- 时间范围（最长 90 天）
- 金额范围
- 商户 ID / 持卡人 ID / 卡 BIN
- 模型版本

### 5.4 交易详情页

![交易详情页标签页](screenshots/05_tx_detail_tabs.png)

包含以下标签页：

1. **基本信息**：交易参数、决策、风险评分
2. **模型解释**：SHAP 特征贡献图、TOP-10 重要特征
3. **规则命中**：命中的规则列表、规则版本、DSL
4. **图关系**：账户/卡/设备/IP 的子图（默认 2 跳）
5. **历史行为**：持卡人 30 天交易画像
6. **案件关联**：关联的案件 ID 与时间线
7. **反馈**：提交欺诈标签

### 5.5 反馈真实标签

风控分析师可以在交易详情页点击"标记为欺诈"或"标记为非欺诈"，标签将进入模型再训练数据集。

ℹ️ 标签来源：
- `CHARGEBACK`：拒付调单
- `MANUAL_REVIEW`：人工核实
- `POLICE_REPORT`：报案记录
- `EXTERNAL_LIST`：外部黑名单匹配

## 6. 案件管理

### 6.1 案件列表

![案件列表视图](screenshots/06_case_list.png)

路径：侧边栏 → 案件 → 全部案件

支持的视图：
- **全部案件**：默认列表
- **我的待办**：分配给我的 OPEN 案件
- **未分配**：待分配案件
- **已逾期**：超过 SLA 的案件
- **已关闭**：最近 30 天已结案案件

### 6.2 创建案件

![创建案件表单](screenshots/06_create_case.png)

1. 点击右上角"新建案件"
2. 填写：
   - 关联交易号（可多选）
   - 优先级（P0/P1/P2/P3）
   - 处理人
   - 描述
   - 标签（chargeback/dispute/high_value 等）
3. 点击"创建"

✅ 案件 ID 自动生成，分配人收到通知。

### 6.3 处理案件

#### 6.3.1 案件详情页

![案件详情页布局](screenshots/06_case_detail.png)

- **顶部**：案件 ID、状态、优先级、SLA 倒计时
- **左侧**：关联交易列表、关联团伙、关联账户
- **右侧**：时间线、备注、附件

#### 6.3.2 工作流

```
OPEN（创建） → IN_REVIEW（处理中） → CONFIRMED（确认为欺诈）
                                ↓
                          FALSE_ALARM（误报）
                                ↓
                          CLOSED（已结案）
```

#### 6.3.3 SLA 标准

| 优先级 | 响应 SLA | 解决 SLA |
|--------|----------|----------|
| P0 | 15 分钟 | 4 小时 |
| P1 | 1 小时 | 24 小时 |
| P2 | 4 小时 | 72 小时 |
| P3 | 24 小时 | 7 天 |

⚠️ 超过 SLA 的案件会自动升级到处理人的上级。

### 6.4 添加备注

1. 案件详情页右侧"备注"区
2. 输入备注内容
3. （可选）@提及同事
4. 点击"提交"

ℹ️ 备注一旦提交不可删除，仅可编辑（保留历史版本）。

### 6.5 上传附件

支持格式：PDF、PNG、JPG、CSV、XLSX，单文件 ≤ 50MB。

🔥 严禁上传明文 PAN（卡号），系统会自动扫描并阻断。

### 6.6 结案

1. 点击"结案"按钮
2. 选择结案结论：
   - `CONFIRMED_FRAUD`：确认欺诈
   - `FALSE_ALARM`：误报
   - `INCONCLUSIVE`：证据不足
3. 填写：
   - 损失金额（分）
   - 挽回金额（分）
   - 是否上报反洗钱
   - 结案说明
4. 二次确认后提交

✅ 结案后案件进入只读状态，可重新打开（生成新案件 ID）。

### 6.7 案件导出

- 列表页右上角"导出"按钮
- 支持 CSV / Excel
- 含完整审计字段
- 导出操作记录到审计日志

## 7. 规则引擎管理

### 7.1 规则列表

路径：侧边栏 → 规则 → 全部规则

### 7.2 规则生命周期

```
DRAFT（草稿） → CANARY（金丝雀） → ACTIVE（已生效） → RETIRED（已退役）
```

ℹ️ 依据 FRD-BASELINE-V1.1 §3.4，规则状态枚举为：`DRAFT | CANARY | ACTIVE | RETIRED`，规则动作枚举为：`BLOCK | REVIEW`。

### 7.3 创建规则

📋 操作前准备：
- 已分析业务场景
- 已准备 DSL 草稿
- 已评估潜在误报影响

#### 7.3.1 DSL 语法

```sql
-- 简单条件
amount > 1000000 AND hour_of_day BETWEEN 2 AND 5

-- 复杂条件（带聚合）
SUM(amount, 1h, user_id) > 5000000
  AND COUNT(DISTINCT merchant_id, 1h, user_id) > 5
  AND ip_country != billing_country

-- 引用外部变量
device_age_sec < 600
  AND user_total_tx_count < 3
```

#### 7.3.2 操作步骤

![创建规则表单](screenshots/07_create_rule.png)

1. 点击"新建规则"
2. 填写名称、描述
3. 编写 DSL
4. 选择严重级别（INFO/WARN/BLOCK）
5. 选择动作（BLOCK/REVIEW）
6. 配置生效时间范围
7. 配置渠道范围
8. 保存为草稿

### 7.4 DSL 校验与试运行

1. 规则详情页点击"校验"
2. 系统自动检查语法
3. （可选）选择样本交易进行试运行
4. 查看命中率、误报率预估

⚠️ 试运行不会影响生产决策，仅返回模拟结果。

### 7.5 规则评审与发布

#### 7.5.1 提交评审

1. 草稿完成后点击"提交评审"
2. 选择评审人（至少 1 名，建议 2 名）
3. 填写变更说明

#### 7.5.2 评审

- 评审人收到通知
- 查看变更对比（diff）
- 批准 / 拒绝（含意见）
- 至少 1 名评审人批准后可发布

#### 7.5.3 发布

1. 评审通过后点击"发布"
2. 二次确认
3. 规则进入 ACTIVE 状态
4. 默认 5 分钟内全节点生效

🔥 严重级别为 BLOCK 的规则发布需 TENANT_ADMIN 二次确认。

### 7.6 规则监控

- **命中率**：24h/7d/30d 命中次数与占比
- **误报率**：基于结案数据反推
- **性能**：平均执行时间
- **趋势图**：命中数趋势

⚠️ 误报率 > 30% 的规则系统会自动告警，建议下线优化。

### 7.7 规则下线

1. 规则详情页点击"下线"
2. 选择下线原因
3. 二次确认
4. 规则进入 DISABLED 状态
5. 30 天后自动归档

## 8. ML 模型治理

### 8.1 模型列表

路径：侧边栏 → 模型 → 全部模型

字段：
- 模型 ID / 版本
- 状态：`REGISTERED | CANARY | ACTIVE | RETIRED`（依据 FRD-BASELINE-V1.1 §3.3 模型状态枚举）
- 流量比例
- AUC / Precision / Recall
- 训练时间 / 上线时间

### 8.2 模型详情

#### 8.2.1 性能指标

- AUC、PR-AUC、KS
- Precision@1%、Recall@1%（目标 Recall@1%FPR ≥ 0.85）
- F1、MCC
- 延迟分布（P50/P95/P99，目标 P99 < 200ms）
- 各子集表现（按金额段、渠道、商户类别）

#### 8.2.2 特征重要性

- 全局特征重要性（Gain / Weight）
- 特征稳定性（PSI）
- 特征覆盖度

#### 8.2.3 漂移监控

- 整体 PSI（1d / 7d / 30d）
- KL 散度
- 各特征 PSI 排行
- 预测分布对比

⚠️ 7d PSI > 0.25 触发漂移告警，建议启动再训练。

### 8.3 金丝雀发布

#### 8.3.1 启动金丝雀

![启动金丝雀发布配置](screenshots/08_canary_start.png)

1. 选择候选模型（必须为 REGISTERED 状态）
2. 配置：
   - 初始流量比例（默认 5%）
   - 回滚阈值（precision_drop / latency / error_rate）
   - 观察期（默认 24h）
3. 提交评审
4. ML 工程师 + TENANT_ADMIN 双确认
5. 启动金丝雀（模型状态变为 CANARY）

#### 8.3.2 三阶段推进

```
Stage 1: 5% 流量，24h 观察
   ↓ 满足阈值
Stage 2: 25% 流量，24h 观察
   ↓ 满足阈值
Stage 3: 100% 流量（晋升为 ACTIVE）
```

ℹ️ 任何阶段触发回滚阈值，系统自动回滚到上一稳定版本。

#### 8.3.3 推进流量

1. 金丝雀详情页点击"推进到下一阶段"
2. 系统校验上一阶段是否满足条件
3. 二次确认
4. 流量比例自动调整

#### 8.3.4 紧急回滚

1. 金丝雀详情页点击"紧急回滚"
2. 填写回滚原因
3. 二次确认
4. 流量立即切回上一稳定版本（< 30s）
5. 自动触发告警通知

### 8.4 模型回退策略

系统在 ML 引擎异常时按以下顺序回退：

```
BERT 文本模型 → TF-IDF/LR → 启发式规则 → 纯规则引擎
```

### 8.5 Kill Switch

🔥 **紧急熔断开关**

- 路径：模型 → 治理 → Kill Switch
- 触发后立即关闭 ML 引擎，所有交易走纯规则模式
- 需填写：原因、持续时长（最长 24h）、审批人
- 启动后系统进入"降级模式"告警状态

   - 权限范围（多选）：
     - `score:write`（评分请求）
     - `transaction:read`（交易查询）
     - `appeal:write`（申诉提交）
     - `webhook:manage`（Webhook 管理）
   - 有效期（7 天 / 30 天 / 90 天 / 永久，建议 ≤ 90 天）
3. 点击"创建"
4. 系统展示 Key ID + Secret（**Secret 仅展示一次，关闭后不可再查看**）
5. 立即复制保存到密钥管理系统

🔥 切勿将 Secret 提交到代码仓库或日志中。系统会对所有 API 请求中的 Secret 进行脱敏审计。

#### 13.6.2 查看 API Key

- 列表展示：Key ID、名称、环境、权限范围、状态（`ACTIVE | DISABLED | EXPIRED`）、创建时间、最后使用时间
- 点击 Key ID 查看详情（不含 Secret）
- 支持查看最近 100 次调用日志（时间、IP、结果）

#### 13.6.3 撤销 API Key

1. API Key 列表点击"撤销"
2. 选择撤销原因（泄露 / 轮换 / 不再使用）
3. 二次确认
4. Key 立即失效（状态变为 `DISABLED`），所有使用该 Key 的请求返回 401
5. 操作记录到审计日志

⚠️ 建议每 90 天轮换一次 API Key，遵循密钥轮换最佳实践。

### 14.3 规则审批工作流

![规则审批工作流](screenshots/14_rule_approval_workflow.png)

路径：风控经理工作台 → 规则审批

风控经理负责规则从创建到全量发布的审批把关，工作流如下：

```
DRAFT（创建） → REVIEW（评审） → CANARY（灰度） → ACTIVE（全量）
```

#### 14.3.1 评审阶段

1. 规则运营员/风控分析师提交规则草稿至评审
2. 风控经理收到评审通知
3. 在规则审批页查看：
   - 规则 DSL 与变更 diff
   - 试运行报告（命中率、误报率预估）
   - 潜在影响分析
4. 审批操作：
   - **批准**：进入灰度阶段
   - **拒绝**：退回草稿，附意见
   - **需修改**：退回草稿，附修改建议

#### 14.3.2 灰度阶段（CANARY）

![规则灰度配置](screenshots/14_rule_canary_config.png)

1. 评审通过后，风控经理配置灰度：
   - 灰度流量比例（默认 5%）
   - 灰度时长（默认 24h）
   - 观察指标阈值（命中率上限、误报率上限、性能影响）
2. 点击"启动灰度"，规则状态变为 `CANARY`
3. 灰度期间系统自动采集指标，风控经理在灰度监控页查看：
   - 实际命中率 vs 预估
   - 实际误报率
   - 规则执行耗时
   - 对应交易样本
4. 灰度到期后系统自动生成灰度报告

#### 14.3.3 全量发布（ACTIVE）

1. 灰度报告达标后，风控经理点击"全量发布"
2. 系统校验灰度指标是否满足阈值
3. 二次确认（BLOCK 级规则需 TENANT_ADMIN 二次确认）
4. 规则状态变为 `ACTIVE`，5 分钟内全节点生效
5. 发布记录到审计日志

#### 14.3.4 灰度回滚

- 灰度期间触发阈值，系统自动回滚（规则回到 DRAFT）
- 风控经理可手动点击"终止灰度"
- 回滚记录到审计日志

## 15. 常见问题

### 15.1 登录问题

**Q1: 忘记密码怎么办？**
A: 登录页点击"忘记密码"，通过邮箱重置。如邮箱不可用，联系 TENANT_ADMIN 重置。

**Q2: MFA 设备丢失怎么办？**
A: 使用恢复码登录后重新绑定 MFA。如恢复码也丢失，联系 TENANT_ADMIN 重置（需身份验证）。

**Q3: 账号被锁定怎么办？**
A: 等待 15 分钟自动解锁，或联系 TENANT_ADMIN 手动解锁。

### 15.2 业务问题（风控分析师/经理）

**Q4: 交易被误判为欺诈怎么办？**
A: 在交易详情页标记为"NOT_FRAUD"反馈，并创建案件记录误报，规则运营员可优化规则。

**Q5: 规则命中率突降怎么办？**
A: 检查上游数据源是否正常，规则 DSL 是否依赖异常字段，必要时下线规则并联系 ML 工程师。

**Q6: 模型 AUC 下降怎么办？**
A: 检查漂移 PSI，如 > 0.25 触发再训练。可在模型详情页查看影响 AUC 的因素，并启动金丝雀发布新模型。

**Q7: 金丝雀发布失败如何回滚？**
A: 系统会自动回滚。如未自动触发，可手动点击"紧急回滚"，30 秒内流量切回。

**Q8: 案件 SLA 即将超时如何处理？**
A: 风控经理可在案件详情页"延长 SLA"（≤ 原始 SLA 50%），或重分配给负载较低的分析师。P0 案件超时会自动升级到 TENANT_ADMIN。

**Q9: 如何批量分配未处理案件？**
A: 风控经理在"案件 → 未分配"页勾选多案件，点击"批量分配"，选择均衡分配/按技能匹配/指定人员策略。

### 15.3 商户问题（MERCHANT_ADMIN）

**Q10: 交易被拦截后如何申诉？**
A: 在"交易查询"页找到被拦截交易，点击"申诉"，填写申诉理由与类型，上传补充材料后提交。标准处理时限 3 工作日，紧急申诉 24h（需 TENANT_ADMIN 审批）。申诉状态可在"我的申诉"页跟踪。

**Q11: Webhook 投递失败怎么办？**
A: 系统会自动重试 5 次（指数退避：1min/5min/30min/2h/6h）。连续失败 5 次后 Webhook 自动禁用并邮件通知。排查步骤：(1) 在"投递日志"页查看失败原因（超时/非 2xx/连接拒绝）；(2) 检查回调 URL 是否可公网访问且为 HTTPS；(3) 检查服务端是否正确返回 2xx；(4) 修复后重新启用 Webhook 并点击"测试"验证。

**Q12: API 限流如何提升？**
A: 默认按租户套餐限流（STANDARD/PRO/ENTERPRISE）。如频繁返回 429，可：(1) 优化调用方批量逻辑，减少 QPS；(2) 联系 TENANT_ADMIN 升级套餐；(3) 错峰调用。限流响应头 `X-RateLimit-Remaining` 显示剩余配额。

**Q13: 如何查看商户风险画像？**
A: 商户门户 → 风险画像，可查看风险等级、风险评分、各维度（交易/行为/合规/设备）风险指标、30/90 天趋势与改善建议。风险画像每日凌晨更新。

**Q14: API Key 如何安全保管？**
A: (1) Secret 仅在创建时展示一次，务必立即保存到密钥管理系统；(2) 切勿提交到代码仓库或日志；(3) 建议每 90 天轮换；(4) 如怀疑泄露立即在"API Key 管理"页撤销；(5) 生产与沙箱环境使用不同 Key。

**Q15: 商户入驻 KYC 审核要多久？**
A: 标准审核 2 个工作日内完成。审核结果有三种：通过（进入 API Key 签发）、拒绝（附原因，可修改后重新提交）、补充资料（附需补充清单）。可登录商户门户查看审核进度。

**Q16: 如何切换到生产环境？**
A: KYC 审核通过后默认分配 sandbox 环境。切换生产环境步骤：(1) 在 sandbox 完成联调；(2) 在"API Key 管理"页申请新建 production 环境 Key；(3) 提交申请后由 TENANT_ADMIN 二次审批；(4) 审批通过后 production Key 生效。

### 15.4 合规问题（COMPLIANCE_OFFICER/AUDITOR）

**Q17: 如何生成反洗钱报告？**
A: 案件详情页点击"上报反洗钱"，选择上报类型（STR 可疑交易报告/CTR 大额交易报告），系统自动生成 PDF 报告。依据 FRD-BASELINE-V1.1 §7.3，上报通道由客户/第三方提供接口，FRD 完成对接联调。

**Q18: 审计日志能否删除？**
A: 不能。审计日志不可篡改、不可删除，保留 7 年（满足反洗钱法要求）。

**Q19: 如何申请数据导出？**
A: 联系 COMPLIANCE_OFFICER，提交数据主体请求。系统提供 PIPL 接口：`POST /pipl/data-export` 申请导出，`GET /pipl/data-export/{task_id}/status` 查询状态，系统将在 30 天内响应。

**Q20: 如何配合 PIPL 数据导出？**
A: 数据主体（或其授权人）通过 `POST /pipl/data-export` 提交导出申请。COMPLIANCE_OFFICER 在"PIPL 合规 → 数据主体请求"页审核身份后触发导出。系统汇总该数据主体的所有个人数据（交易、评分、案件、审计记录等），生成加密包供下载，30 天内响应。导出操作全程记录审计日志。

**Q21: PCI-DSS 评估如何配合？**
A: 依据 FRD-BASELINE-V1.1 §2.3，PCI-DSS v4.0 由 QSA 季度评估。配合步骤：(1) COMPLIANCE_OFFICER 在"审计 → PCI-DSS"页导出 RoC 报告编号与日期作为验收证据；(2) 提供 CDE（持卡人数据环境）边界图与网络隔离配置；(3) 提供 Tokenization 实施证明（无明文 PAN 存储）；(4) 配合 QSA 现场抽查审计日志与访问控制；(5) 整改项在限期内完成。

**Q22: 数据删除请求会影响风控吗？**
A: PIPL 数据删除请求会删除数据主体的个人数据，但保留法律要求的最小集（如反洗钱法要求的交易记录）。已用于模型训练的历史特征会做匿名化处理（不可逆关联到个人）。删除后该数据主体的新交易评分不受历史数据影响，但实时规则引擎仍正常工作。

**Q23: 同意撤回后交易还能评分吗？**
A: 依据 FRD-BASELINE-V1.1 §3.11，同意状态为 `GRANTED | WITHDRAWN | EXPIRED`。同意用途 `TRANSACTION_SCORING` 撤回后，系统不再对该数据主体进行 ML 模型评分，但仍可走纯规则引擎（规则引擎不依赖个人特征聚合）。同意用途 `FRAUD_DETECTION` 撤回后，案件中的该数据主体信息会被匿名化。同意管理通过 `POST /consent` 接口操作。

### 15.5 运维问题（DEVOPS_OPS）

**Q24: 如何切换 Kill Switch？**
A: (1) 路径：模型 → 治理 → Kill Switch；(2) 点击"启动熔断"；(3) 填写原因、持续时长（最长 24h）、审批人；(4) 二次确认后立即生效，所有交易走纯规则模式；(5) 系统进入"降级模式"告警状态，CRITICAL 告警推送 TENANT_ADMIN；(6) 到期自动恢复，或手动点击"解除熔断"。

**Q25: 模型回滚多久生效？**
A: 紧急回滚流量切回上一稳定版本 < 30 秒。应用层镜像回滚 ≤ 5 分钟。总体 RTO ≤ 30 分钟（应用层 5min + 数据库 30min，依据 FRD-BASELINE-V1.1 §8.3）。回滚后自动触发告警通知 ML 工程师、风控经理、TENANT_ADMIN。

**Q26: 灰度发布期间出问题怎么办？**
A: 依据 FRD-BASELINE-V1.1 §8.2，灰度分 5%→25%→100% 三阶段，每阶段 24h。出问题时：(1) 触发回滚阈值（precision_drop/latency/error_rate）系统自动回滚；(2) 风控经理可手动"紧急回滚"；(3) 模型回 Stage 1 重新观察或回 REGISTERED 状态分析原因；(4) 记录到审计日志并生成事故报告。

**Q27: 如何查看系统健康状态？**
A: (1) 控制台仪表盘查看 P99 延迟、TPS、AUC、PSI 等关键指标；(2) 运维工程师可访问 Prometheus + Grafana 监控大盘（组件级指标）；(3) Jaeger 查看链路追踪；(4) Loki 查看日志；(5) CRITICAL 告警通过邮件+短信+Webhook 推送。SLA 目标 99.5%（MVP）/ 99.9%（生产稳态）。

**Q28: 等保测评需要配合什么？**
A: 依据 FRD-BASELINE-V1.1 §7.2，等保 2.0 三级覆盖 6 类控制点：物理与环境安全、安全通信网络、安全区域边界、安全计算环境、安全管理中心、剩余信息保护。配合步骤：(1) M1 即启动备案（周期 3-6 个月）；(2) 提供测评机构备案证明编号作为验收证据；(3) 提供 VPC + 安全组 + NetworkPolicy 配置；(4) 提供堡垒机 + HIDS + 主机加固证据；(5) 配合现场测评与整改。
