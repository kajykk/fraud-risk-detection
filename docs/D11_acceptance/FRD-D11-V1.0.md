## 1. 验收概述

### 1.1 验收目的

- 验证 FRD 系统满足合同与需求规格说明书（D02）的全部要求
- 验证系统达到上线部署方案（D10）的生产标准
- 验证系统通过合规审计（PCI-DSS / PIPL / 反洗钱法）
- 确认系统可正式交付客户使用
- 完成项目向运维的正式移交

### 1.2 验收范围

| 类别 | 范围 |
|------|------|
| 功能 | FRD-D02 全部需求项 |
| 性能 | 评分接口、查询接口、并发能力 |
| 安全 | OWASP Top 10、PCI-DSS、PIPL |
| 合规 | PCI-DSS v4.0、PIPL、反洗钱法、等保 2.0 三级 |
| 可靠性 | SLA、故障恢复、灾备 |
| 可观测性 | 监控、告警、日志、追踪 |
| 文档 | D01-D11 全套文档 |
| 运维 | 运维手册、应急预案、知识转移 |

### 1.3 验收依据

- 项目合同
- FRD-D01 项目立项报告
- FRD-D02 需求规格说明书
- FRD-D03 系统架构设计
- FRD-D04 数据库设计
- FRD-D05 API 接口规范
- FRD-D07 测试计划与测试报告
- FRD-D10 上线部署方案
- PCI-DSS v4.0 标准
- PIPL（个人信息保护法）
- 反洗钱法
- GB/T 22239 等保 2.0 三级

## 2. 验收原则

### 2.1 核心原则

1. **以需求为基线**：所有验收项必须可追溯到 D02 需求规格说明书
2. **以证据为准绳**：每项验收必须提供客观证据（测试报告、日志、截图）
3. **零容忍硬约束**：PCI-DSS、PIPL、安全漏洞等硬约束 0 容忍
4. **分级分阶段**：按阶段逐步验收，每阶段达到标准方可进入下一阶段
5. **客户全程参与**：UAT 阶段客户必须深度参与并签字
6. **可追溯**：所有验收记录归档，可追溯到具体测试用例与执行结果

### 2.2 通过标准

| 验收项 | 通过标准 |
|--------|----------|
| P0 阻断缺陷 | 0 遗留 |
| P1 严重缺陷 | ≤ 2 遗留（必须有缓解措施） |
| P2 一般缺陷 | ≤ 10 遗留（必须有修复计划） |
| P3 轻微缺陷 | ≤ 30 遗留（可后续修复） |
| 单元测试通过率 | ≥ 99% |
| 集成测试通过率 | ≥ 95% |

| 合规违反 | 0 |
