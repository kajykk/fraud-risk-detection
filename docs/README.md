## 项目简介

FRD（Financial Fraud Detection）是一个面向持牌金融机构的实时反欺诈 SaaS 平台，集成**规则引擎 + ML 多模态融合 + GNN 团伙检测**三大核心能力，满足 **PCI-DSS v4.0 / PIPL / 反洗钱法 / 等保 2.0 三级**合规要求。

| 维度 | 关键能力 |
|------|----------|
| 双轨决策 | 规则引擎 + ML 引擎并行，支持 ALLOW / REVIEW / DENY / CHALLENGE 四档决策 |
| 多模态融合 | 结构化 + 文本（BERT）+ 行为时序，复用 DWS 心理健康系统融合架构 |
| 团伙检测 | GNN + Neo4j 图数据库，识别账户/设备/IP/卡团伙 |
| 模型治理 | 金丝雀发布（5%→25%→100%）+ PSI/KL 漂移检测 + 自动回滚 + Kill Switch |
| 合规安全 | PCI-DSS Token 化 + PIPL 数据主体权利 + 反洗钱 STR/CTR 上报 |
| 可观测性 | Prometheus + Grafana（Loki / Jaeger 于 M6 前补齐） |
| 高可用 | K8s 单 AZ 起步（生产稳态扩多 AZ），SLA 99.5%（MVP）/ 99.9%（生产稳态），RTO ≤ 30min |

## 关键技术栈

### 后端
- **语言/框架**：Python 3.12 · FastAPI · SQLAlchemy 2.0 (async) · Pydantic 2.7
- **数据库**：PostgreSQL 15（主从）· Redis 7（哨兵）· Neo4j 5 社区版（单主 + 异地备份，第 2 年起评估升级 Enterprise）
- **异步任务**：Celery 5.4 + Celery Beat
- **ML**：XGBoost · PyTorch · Transformers (BERT) · scikit-learn
- **GNN**：PyTorch Geometric (PyG)

### 前端
- **框架**：Vue 3.5 (Composition API) · TypeScript 5.6 · Vite 6
- **UI 库**：Element Plus · ECharts · vis-network（图谱可视化）
- **PWA**：vite-plugin-pwa · Workbox

### DevOps
- **容器化**：Docker + Kubernetes（单 AZ 起步，生产稳态扩多 AZ）
- **CI/CD**：GitHub Actions + ArgoCD（GitOps）
- **可观测性**：Prometheus + Grafana（Loki / Jaeger 于 M6 前补齐）
- **IaC**：Terraform + Helm

## 性能与质量目标

> 依据 FRD-BASELINE-V1.1 §2.1 统一，分两阶段：MVP（单实例）→ 生产稳态（集群扩容后）。

| 维度 | 目标 |
|------|------|
| 评分接口 P99 | < 200ms |
| 单实例 TPS | ≥ 1000 |
| 集群 TPS | ≥ 2000（MVP）/ ≥ 10000（生产扩容后） |
| 系统可用性 | ≥ 99.5%（MVP）/ ≥ 99.9%（生产稳态） |
| 单元测试通过率 | ≥ 99% |
| 契约测试通过率 | 100%（或 ≥ 95% 且剩余有书面豁免） |
| 行覆盖率 | 总体 ≥ 85%（评分/规则引擎核心 ≥ 90%，ML/GNN ≥ 75%） |
| 安全高危漏洞 | 0 |
| 模型 AUC | ≥ 0.92 |
| 模型 Recall@1%FPR | ≥ 0.85 |
| 模型 PSI 7d | < 0.25 |
| RTO | ≤ 30min（应用层 5min + 数据库 30min） |
| RPO | ≤ 1min |

## 合规要求

- **PCI-DSS v4.0**：卡数据 Token 化、不存储 PAN、加密传输
- **PIPL**：知情同意、最小化、数据导出/删除权、数据本地化
- **反洗钱法**：KYC、STR/CTR 上报、7 年审计日志保留
- **GB/T 22239 等保 2.0 三级**：物理/网络/主机/应用/数据/管理
